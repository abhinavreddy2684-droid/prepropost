# Media storage

Uploaded files live in one **private** S3-compatible bucket per environment. Django never receives
file bytes: the API hands the browser a pre-signed POST, the browser uploads straight to the
bucket, and reads go through short-lived signed GET URLs. `apps/media_library/storage.py` is the
only module that talks to the storage service.

| Environment | Provider | Settings |
|---|---|---|
| Local | MinIO (`minio` + `minio-init` in docker-compose) | `MEDIA_STORAGE_ENDPOINT_URL=http://minio:9000`, `MEDIA_STORAGE_PUBLIC_ENDPOINT_URL=http://localhost:9000` |
| Staging, production | AWS S3, `ap-south-1` | both endpoint URLs empty; bucket, region and keys from the environment |
| Tests | in-memory fake (`apps.media_library.testing.InMemoryStorage`) | set in `config/settings/test.py` |

The provider is swappable through `MEDIA_STORAGE_BACKEND` and the `MEDIA_STORAGE_*` variables
(see `.env.example`). Any S3-compatible service works with `S3Storage`.

## Object keys

Keys are generated by the server, never from the client's file name:

- original: `{purpose}/{media_id}` (e.g. `talent.gallery/6f1c...`)
- thumbnails: `thumbs/{media_id}/{size}.webp`

## Production bucket setup (per environment)

1. **Create the bucket** in `ap-south-1`, e.g. `prepropost-media-production`. Object ownership:
   bucket owner enforced (ACLs disabled). Default encryption: SSE-S3.
2. **Block all public access**: turn on all four "Block Public Access" settings. Do not add a
   bucket policy that grants anonymous reads; every read is a signed URL.
3. **IAM user limited to the bucket** for the API and the worker:

   ```json
   {
     "Version": "2012-10-17",
     "Statement": [
       {
         "Effect": "Allow",
         "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject"],
         "Resource": "arn:aws:s3:::prepropost-media-production/*"
       },
       {
         "Effect": "Allow",
         "Action": ["s3:ListBucket"],
         "Resource": "arn:aws:s3:::prepropost-media-production"
       }
     ]
   }
   ```

   Put its key pair in `MEDIA_STORAGE_ACCESS_KEY_ID` / `MEDIA_STORAGE_SECRET_ACCESS_KEY` (or use an
   instance role and leave them empty). `s3:ListBucket` lets a HEAD on a missing key return 404
   rather than 403.
4. **CORS with exact origins** (never `*`). Only the frontend origins, only POST and GET, and
   expose `ETag`:

   ```json
   [
     {
       "AllowedOrigins": ["https://app.prepropost.example"],
       "AllowedMethods": ["POST", "GET"],
       "AllowedHeaders": ["*"],
       "ExposeHeaders": ["ETag"],
       "MaxAgeSeconds": 3000
     }
   ]
   ```

   Keep this list equal to `MEDIA_CORS_ALLOWED_ORIGINS`.
5. **Lifecycle rule** (optional safety net): abort incomplete multipart uploads after 1 day. The
   application deletes expired and discarded objects itself (`expire_pending_uploads`,
   `purge_discarded_media`).

## Local MinIO

`make up` starts MinIO on `localhost:9000` (console on `localhost:9001`) and runs
`scripts/minio-init.sh` once: it creates the bucket, keeps it private and applies CORS for
`MEDIA_CORS_ALLOWED_ORIGINS`. MinIO builds without per-bucket CORS fall back to the server-wide
`MINIO_API_CORS_ALLOW_ORIGIN`, which compose sets to the same exact origins.

## Tests

Unit tests use the in-memory fake. Storage integration tests (`-m minio`) run against a real
MinIO when `MEDIA_TEST_S3_ENDPOINT` is set; CI starts one. Locally:

```bash
docker run -d -p 9000:9000 quay.io/minio/minio:RELEASE.2025-04-22T22-12-26Z server /data
MEDIA_TEST_S3_ENDPOINT=http://localhost:9000 pytest -m minio
```
